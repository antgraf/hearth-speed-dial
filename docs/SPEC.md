# Hearth Speed Dial — product spec

Status: Manifest V3 new-tab speed dial of the bookmark tree for **Chrome and Firefox**; create, rename, delete; drag reorder and drag into folders; **find-a-dial search** across the open folder and nested dials (titles + URLs; `/` focuses, `Esc` clears); grid columns/tile size, thumbnail wait time, optional default folder for new windows, display-order reverse, and a local **Theme** surface (appearance mode auto-by-default/light/dark, ember-preserving accent palette, optional solid background color, optional locally uploaded wallpaper with fit/position/opacity) in an in-page **Settings** overlay (gear; 16:9 faces, width up to 576px; `settings.html` remains a secondary options entry); a dismissible **first-run welcome** card on the dial (bookmarks-as-store, gear → Settings, Picture… for images; **Open Settings** / **Got it**; dismissed flag in `storage.local`); **export / import** of dial pictures and non-bookmark prefs as a downloadable JSON backup (bookmarks stay in the browser; import offers overwrite or merge); context-menu **Add to Hearth…** with folder picker (http/https pages only); dial pictures from a local file, an image URL (fetched once into local storage), or an optional captured thumbnail; **Refresh All Thumbnails** for http(s) bookmarks in the currently open dial folder (folder ⋮ + right-click on the dial page); title-strip favicons from Chrome’s local profile cache for http(s) bookmarks (Firefox: no equivalent without host access — title icons omitted); monogram fallback for bookmark dial faces and a folder icon for folders; in-page dialogs for rename, delete confirm, settings, and ⋮ action menus (tile + current folder). Create uses one **New** control that chooses folder vs bookmark. Refresh of a single dial remains later vision.

## Vision

Hearth Speed Dial replaces the new tab with a grid of sites you can see, group in folders, and rearrange. Adding a page can show a picture of that site. The extension keeps no account and does not upload the dial list, images, or usage anywhere. Every dial is an ordinary browser bookmark, folders included, so browser sync is the cloud copy and the bookmark manager edits the same tree.

Refresh of a whole open folder’s thumbnails is in product scope (current-folder only; nested folders skipped). Refresh of one dial remains vision and is not required yet. Image URLs and optional thumbnail capture are in product scope under the opt-in permission model below.

## Product bar (Chrome + Firefox MV3)

Chrome and Firefox, Manifest V3. Load unpacked from `dist/chrome/` (Chrome) or `dist/firefox/` (Firefox). One extension per browser, one new-tab page. Shared TypeScript prefers the promise-based `browser` namespace when present (Firefox) and falls back to `chrome` (Chromium).

- A customizable grid: column count (**1–8**) and dial face width (faces are **16:9**, width up to 576px), saved in extension `storage.local` and edited from the new-tab **Settings** overlay (gear; categorized Layout / Display / Theme / Pictures / Backup / Danger Zone, scrollable; Danger Zone stays last). That overlay can also reverse display order so last bookmarks appear first (display preference only; browser bookmark order stays the store of truth). Thumbnail capture wait time (how long to wait after opening the page before the screenshot, default **2s**, range 1–15s) is editable there too. An optional **default folder for new windows** can pin the folder opened on each new window / initial new-tab; when unset, Hearth recalls the last open folder. **Theme** controls appearance mode (**auto** via `prefers-color-scheme` by default; **light** / **dark** to lock), a small warm accent palette that keeps Hearth’s ember identity (not a full arbitrary recolor), an optional solid background color, and an optional **locally uploaded** wallpaper (fit / position / opacity; stored as a data URL in extension local storage — no remote wallpaper providers, no Google Fonts CDN). **Backup** exports dial pictures (`hearth.image.*`), theme wallpaper (`hearth.theme.background`), and layout/theme prefs (settings blob) as a downloadable JSON file — browser bookmarks are not included. **Import** validates the file and asks **overwrite** (replace local Hearth settings, wallpaper, and all dial pictures) or **merge** (apply settings and add/replace pictures from the file; keep local pictures absent from the backup). `settings.html` / `options_page` remains a secondary entry from the browser’s extension details.
- The new tab is a grid of the open bookmark folder. The browser’s bookmark root is that same grid of folders. Nested folders open in the grid. A new tab reopens the last folder unless a default folder is set. The bookmark’s title, URL, parent, and order are the source of truth. The open folder can gain a new folder or bookmark from a single **New** control (chooser for folder vs bookmark).
- **First-run welcome**: on the first new-tab open (until dismissed), a static card above the dial teaches that bookmarks are the dial store, the gear opens Settings, and **Picture…** assigns images. Primary **Open Settings** opens the in-page Settings overlay; secondary **Got it** dismisses and persists `hearth.welcome.dismissed` in `storage.local` (device-local; cleared by Erase All Data; not part of backup / sync). No permission prompts, image toggles, or custom illustration on the card. English copy via `_locales` + `t()`.
- **Find-a-dial search** filters the open folder and its nested dials by title or URL (bookmark data already in memory — no new permission). Press `/` to focus the field; `Esc` clears the query. While a query is active, the create tile is hidden and drag-reorder is paused; opening a folder clears the filter so the destination shows fully.
- Drag a dial to reorder it or move it, including into another folder in the tree.
- Right-click a normal web page to add it as a bookmark in a folder of the dial tree, including a nested folder. **Add to Hearth…** is limited to `http://` / `https://` documents via `documentUrlPatterns` so it does not appear on Hearth’s own extension dial page (`chrome-extension://` / `moz-extension://`). On that dial page, right-click instead offers **Refresh All Thumbnails** (same action as the folder ⋮ item).
- A dial with no picture shows a monogram for bookmarks, or a folder icon for folders. Beside the title on http(s) bookmark tiles, **Chrome** shows a small site icon from the local favicon cache (`favicon` permission + `_favicon` URL — profile cache only; no network and no third-party icon CDN). **Firefox** has no equivalent local API without host access; title icons are omitted there (monogram / folder icon on the dial face stay the fallback). A missing Chrome cache entry or load error hides the title icon. The user can assign a picture by:
  - attaching one local image file (large / high-res files are decoded, downscaled, and compressed on ingest before persist — dial tiles up to **1280×720**, theme wallpapers up to **2560×1440**, stored payload about **1.5 MB**; decode or store failures surface a clear error), or
  - entering an image URL (http/https) when that opt-in is on. Hearth fetches the image **once**, runs the same ingest resize path, and stores it as a local data URL in extension `storage.local` (same store as file attach). The dial does **not** hotlink the remote URL afterward.
  - capturing a page thumbnail when that opt-in is on (see Permissions).
  - **Refresh All Thumbnails** (current open folder): recaptures http(s) bookmark dials in that folder using the same temporary-window capture path as **Capture thumbnail**. Nested folder contents and folder tiles are skipped. Confirm before replacing existing dial pictures. Requires the thumbnail Settings opt-in and optional permissions; does not force-enable them. Available from the current-folder **⋮** menu and from a dial-page browser context menu (see below).
- **Thumbnail generation** is optional and **disabled by default** in Settings. Enabling it calls `permissions.request` for the optional permissions needed to open the page and capture a screenshot. On grant, the tile **Picture…** menu offers **Capture thumbnail** (temporary window → wait the Settings wait time → `captureVisibleTab` → store JPEG data URL → close window). If the user denies the prompt, or later revokes optional access in the browser’s extension details, the setting stays off / capture degrades gracefully.
- **Assign pictures from URLs** is a separate Settings toggle, also **off by default**. Enabling it requests optional http/https host access. On grant, **Picture… → Image from URL…** is unlocked. Turning the toggle off calls `permissions.remove` for those http/https grants (not `tabs` / `<all_urls>` used by thumbnails), so active access drops while the setting is off. Chrome usually restores a previously allowed optional grant on the next enable **without** showing the dialog again; Firefox may re-prompt more often. Deny or revoke degrades gracefully like thumbnails. Optional permissions are **not** requested at install or on first new-tab open.
- No account, no analytics, and no request to a service run for this extension.

Default install permissions stay narrow: `bookmarks`, `storage`, `unlimitedStorage` (local dial pictures only — lifts the default shared quota; no network, no sync of blobs), `contextMenus`, and `activeTab` (temporary tab title for **Add to Hearth…** after the context-menu gesture). **Chrome** also installs `favicon` (profile favicon cache for title-strip icons only — no network). **Firefox** omits `favicon`. Host access and `tabs` are **optional** (see Permissions).

Out of scope for now: refresh one dial; favicon-as-dial-face fallback; Firefox title-strip favicons (no local-only API without host permissions). English `_locales` scaffolding is in (`_locales/en/messages.json` + runtime `t()` via `browser.i18n` / `chrome.i18n`); additional languages remain out of scope.

## Permissions

| Kind | Permissions | When |
| --- | --- | --- |
| Always on | `bookmarks`, `storage`, `unlimitedStorage`, `contextMenus`, `activeTab` | Install on Chrome and Firefox (`unlimitedStorage` is local dial art only — no network / no blob sync; `activeTab` only unlocks the clicked tab for the gesture — used to prefill the dial name from the page title) |
| Always on (Chrome only) | `favicon` | Install on Chrome (`favicon` is Chrome’s local profile cache for title-strip icons — no network / no third-party CDN). Omitted from the Firefox manifest. |
| Optional | `tabs` + host `<all_urls>` | Only when the user enables **Generate dial thumbnails** in Settings |
| Optional | Host `http://*/*` + `https://*/*` | Only when the user enables **Assign pictures from URLs** in Settings. Chrome lists those in `optional_host_permissions` (plus `<all_urls>` for thumbnails). Firefox folds the same host patterns into `optional_permissions`. Turning the toggle off removes those http/https grants from the **active** set. |

**Choice:** The two opt-ins are independent. Thumbnails keep `tabs` + `<all_urls>`; URL fetch uses the http/https scheme wildcards. If thumbnails already granted `<all_urls>`, URL fetch can use that host access when its own toggle is on (no second host prompt). Turning URL fetch off does **not** revoke thumbnail `<all_urls>` / `tabs`. Toggle-off `permissions.remove` drops active capability; Chrome’s optional-permission “granted” memory means a later `permissions.request` for the same grant typically returns true without a dialog (documented Chrome behavior). Always-on install permissions stay narrow aside from `unlimitedStorage` (local dial pictures) and Chrome’s `favicon` (local cache for title icons — install-time so a fresh install over a real bookmark tree is recognizable without assigning pictures). Settings shows a simple dial-picture storage usage line; assign/capture write failures (full disk / remaining browser limits) surface an honest error instead of failing silently.

## Packaging

| Target | Build | Load / pack |
| --- | --- | --- |
| All (default) | `npm run build` or `.\build.ps1` | Writes `dist/chrome/` and `dist/firefox/` |
| Chrome | `npm run build:chrome` or `.\build.ps1 -Target Chrome` | Load unpacked `dist/chrome/`; `npm run pack:chrome` → `artifacts/hearth-speed-dial-chrome-vX.Y.Z.zip` |
| Firefox | `npm run build:firefox` (after Chrome) or `.\build.ps1 -Target Firefox` | Temporary add-on from `dist/firefox/manifest.json` (Firefox **121+**); `npm run pack:firefox` → `artifacts/hearth-speed-dial-firefox-vX.Y.Z.zip`; AMO source archive: `npm run pack:source` → `artifacts/hearth-speed-dial-source-vX.Y.Z.zip` ([AMO.md](./AMO.md)) |

Firefox manifest differences (generated, not hand-edited): omit `favicon`; fold optional hosts into `optional_permissions`; add `browser_specific_settings.gecko` (`id`: `hearth-speed-dial@antgraf`, `strict_min_version`: `121.0`, `data_collection_permissions`: `{ "required": ["none"] }`); use MV3 `background.scripts` (not `service_worker` — temporary add-ons disable SW) + `chrome_url_overrides.newtab`. AMO listing copy / screenshots / privacy policy remain separate Pre-publish items; source-zip rebuild steps are in [AMO.md](./AMO.md).

## Hard requirements this spec is aiming at

These stay the product bar.

1. New-tab speed dial with a customizable grid.
2. Assign an image (local file, or URL / thumbnail when the matching Settings opt-in and optional permissions are granted). Refresh all thumbnails in the open folder is in scope; title-strip favicons from the Chrome local cache are in scope; favicon-as-dial-face and refresh of one dial remain later vision.
3. Add the current page from a right-click, into a chosen folder.
4. Items are normal bookmarks. Sync is the browser’s. The bookmark manager can edit them.
5. Drag to order and to move.
6. Folders nest, and add, drag, and thumbnail refresh (open folder only) apply inside a folder.

## Assumptions

- Dial faces without a picture use a monogram for bookmarks and a folder icon for folders (not the favicon as the face). Title strips on http(s) bookmarks show a small Chrome-cache favicon when available; Firefox omits title icons.
- The right-click item lets the user pick the destination folder. It does not silently use whichever folder is open on the new-tab page.
- Settings that are not bookmarks (grid, display-order reverse, theme prefs + local wallpaper, thumbnail opt-in, thumbnail wait time, last opened folder id, optional default folder for new windows, image blobs, first-run welcome dismissed flag) live in extension storage and do not sync yet. **Export / import** covers decoration prefs (layout/theme/wallpaper/images) as a local JSON backup so they survive profile reset or a new machine; browser bookmarks and the welcome dismissed flag are never written into that file. Dial pictures are keyed by bookmark id and may rematch by URL when ids differ across profiles.
